1 of 11 phases done

From bring-up to Steam, one demo at a time.

Every phase ends with a demo that must work in QEMU and in CI, and no phase starts before the previous one passes. The phases build on each other: a scheduler before processes, processes before a shell, a shell before a desktop.

Phases 0–1 done · Phase 2 next · Phases 3–10 planned

SegOS roadmap, phases 0 to 10
Phase What gets built Done when Effort* Status
0 Bring-up Workspace, xtask, Limine boot, serial + framebuffer console, GDT/IDT, exceptions, physical frame allocator, kernel heap, paging Kernel prints “SegOS” in QEMU, panics show a backtrace, CI boots it 2–4 weeks Done

2 First user process Ring 3, syscall/sysret, ELF loader, address spaces, initramfs (cpio), tmpfs, ~40 syscalls (read, write, mmap, brk, exit, …) A static musl “hello world” built on Linux runs unmodified 1–2 months Next
3 A shell fork with copy-on-write, execve, wait4, pipes, signals, TTY + line discipline, ioctl(TCGETS…), devfs, procfs basics BusyBox sh runs; ls | grep | wc works 2–3 months Planned
4 Real storage PCI, virtio-blk, NVMe, AHCI, page cache, ext4 (read, then write), fat32 for the EFI partition Boots from a disk with a full rootfs 2–3 months Planned
5 glibc and dynamic linking ld-linux.so, threads (clone flags, TLS, futex, set_robust_list), epoll, eventfd, timerfd, signalfd, poll/select, /proc/self/* Unmodified Debian/Artix userland: bash, coreutils, python3, gcc compiling a program 3–4 months Planned
6 Networking virtio-net, e1000, TCP/IP (smoltcp, later own), unix sockets incl. SCM_RIGHTS, netlink (route, uevent) curl https://… and ssh work 2–3 months Planned
7 Graphics and input DRM/KMS on virtio-gpu (then simple-framebuffer, then AMD/Intel), evdev, xHCI + USB HID, memfd, dma-buf SegLinux’s Rust compositor and shell run unchanged on SegOS 4–6 months Planned
8 Desktop apps Sound (virtio-snd, Intel HDA → ALSA interface), inotify, fanotify, seccomp, namespaces (for Flatpak/Chromium sandbox), io_uring subset Firefox, Chromium, LibreOffice, Discord run 6+ months Planned
9 Games Mesa radv/iris on real AMD/Intel GPUs (amdgpu-compatible DRM is the largest single task), ptrace, cgroups v2 subset, Wine/Proton Steam installs; a Proton game runs 1 year+ Planned
10 Release Installer (reusing SegLinux Setup’s design), updates, real-hardware testing, power management (ACPI S3, cpufreq) Installable ISO ongoing Planned

* Rough effort for one or two experienced developers. Source: docs/plan.md.

Honest expectation: a shell in 3–6 months, a desktop with a browser in 2–3 years, Steam games longer. GPU drivers for real hardware are the hardest part, as they were for every other new OS.

Compatibility

How “runs Linux apps” gets measured

Claims are only as good as the tests behind them. These arrive with the phases that make them possible.

Syscall conformance suite

Small programs whose output is recorded on real Linux and compared on SegOS, plus LTP, gVisor’s syscall tests and musl’s libc-test.

Syscall coverage table

Generated from the source: implemented, partial or ENOSYS for all ~360 x86-64 Linux syscalls.

Application ladder

BusyBox → bash → coreutils → python → gcc → curl → weston → SegLinux compositor → Firefox → Steam, run in CI.

strace first

Before working on an application, trace it on Linux to find exactly which syscalls it needs.

Scope

Not on the list (for the first years)

  • Running Linux kernel modules
  • NVIDIA’s proprietary driver
  • Secure Boot signed by Microsoft
  • 32-bit-only hardware
  • Architectures other than x86-64 (aarch64 later)

Kernel code is original, under MIT or Apache-2.0; nothing is copied from Linux (GPL-2.0). Linux source is read for semantics only.
