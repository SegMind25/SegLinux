Early development · Phase 1 of 11 done

A new operating system in Rust that speaks Linux.

SegOS is a kernel written from scratch whose native interface is the Linux system call ABI. The goal: run the applications people already use, unmodified, and Windows programs through Wine and Proton. Today it boots and manages memory. It does not run programs yet.

The idea

Why the Linux ABI means “runs every application”

The programs people actually use (Steam, Firefox, Chromium, Discord, Blender, LibreOffice) already exist as Linux x86-64 binaries. Nobody is going to port them to a new operating system. So instead of asking applications to change, SegOS changes the kernel.

The kernel loads the same ELF files and answers the same system calls, with the same numbers, structures and error codes, and provides the same /proc, /sys and /dev files programs read. Unmodified glibc or musl sits on top, and the application cannot tell the difference.

Windows software then comes along the same way it does on Linux today: Wine and Proton are Linux programs.

This is the route taken by gVisor, Asterinas, Kerla and Maestro, and by FreeBSD’s and Windows’ (WSL1) Linux layers. It is the realistic way for a new kernel to reach real software.

Design

Four decisions that shape everything

01 Linux ABI is the native ABI

Not an emulation layer bolted on the side. There is no second “own” syscall interface to maintain.

02 Monolithic, small unsafe core

All unsafe lives in the HAL and a few audited modules; the rest is #![forbid(unsafe_code)]. No IPC cost per syscall.

03 Drivers speak Linux’s interfaces

DRM/KMS ioctls, evdev and ALSA, so Mesa, libinput and PipeWire work without changes.

04 Measured against real software

A syscall conformance suite compared with real Linux, plus an application ladder from BusyBox up to Steam.

Status

Where it is right now

Each phase ends with a demo that has to work in QEMU. Phases 0 and 1 have passed; Phase 2, the first user program, is next.

Phase 0 · Bring-up Done

  • Boots on UEFI and legacy BIOS via Limine
  • Serial port and framebuffer text console
  • GDT, TSS and IDT; handlers for every CPU exception
  • Physical frame allocator from the boot memory map
  • 4-level paging with a higher-half direct map
  • Kernel heap
  • 7 in-kernel tests passing in QEMU

Phase 1 · Multitasking Done

  • Local APIC timer, calibrated against the PIT
  • Kernel threads and a preemptive scheduler
  • SMP: every CPU started, per-CPU data
  • Interrupt-safe spinlocks, sleeping mutexes, wait queues
  • Kernel stacks with guard pages
  • 13 in-kernel tests passing in QEMU on 4 CPUs

Next, Phase 2: the first user program, a static musl “hello world” built on Linux, running unmodified.

Try it

Build it yourself

You need Rust (the version is pinned in rust-toolchain.toml), QEMU, xorriso, git, make, a C compiler and OVMF. The first build downloads the Limine bootloader into target/limine.

What you will see is the console above: the kernel boots, reports its memory and stops. That is the honest state of things.
